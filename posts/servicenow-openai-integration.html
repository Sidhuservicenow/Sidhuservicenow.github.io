ServiceNow + OpenAI: Building an AI Integration

ServiceNow can act as the enterprise workflow layer while OpenAI provides model capabilities. The key to a maintainable integration is not simply making an API call—it is separating credentials, integration logic, prompts, business rules, and user experience so each layer can be secured and changed independently.

September 2026 · 14 min read · ServiceNow Integration · OpenAI API

Architecture in one sentence: ServiceNow owns the business context and workflow; a server-side integration calls the OpenAI API; the response is validated and returned to the ServiceNow experience.

1. What are we building?

A common enterprise pattern is a ServiceNow experience that sends a user request to an external AI model and then uses the response inside a workflow or user interface. ServiceNow outbound REST integrations use REST Message records to define endpoints, methods, authentication, and headers, and server-side APIs can execute those messages.

OpenAI's current API documentation describes the Responses API as an API surface for direct model requests and tool use, and documents standard API-key authentication using Bearer credentials. OpenAI also states that API keys are secrets and should not be exposed in client-side code.

2. Why use a REST Message?

A REST Message gives the integration a reusable platform configuration rather than scattering endpoint and authentication details throughout scripts. A REST Message can hold the endpoint, authentication, headers, HTTP methods, and related configuration.

  • REST Message: connection details and HTTP configuration.
  • Credential: secret authentication material.
  • Script Include: reusable server-side integration logic.
  • Flow Designer: orchestration and business process.
  • Experience layer: user input and presentation.

3. Configure the OpenAI endpoint

OpenAI's current API reference documents the Responses API and standard Bearer authentication. For a production implementation, use the current endpoint and request schema from the official API reference rather than copying an old model-specific example.

REST Message Name: OpenAI - Responses Endpoint: https://api.openai.com/v1/responses Method: POST Headers: Content-Type: application/json Authorization: Bearer <credential managed by ServiceNow>
Never put a real API key in this HTML article, a public GitHub repository, a client-side JavaScript file, or a ServiceNow widget visible to end users. OpenAI treats API keys as secrets and recommends keeping them on the server side or in a key-management system.

4. Request body design

The request should be generated server-side from controlled inputs. Avoid concatenating arbitrary user text into a privileged instruction set. Keep system-level behavior and business constraints separate from the user's request where your chosen API schema supports that separation.

{ "model": "YOUR_APPROVED_MODEL", "input": "Summarize this incident and identify the likely next troubleshooting step." }

The exact fields and supported model capabilities should be checked against the current OpenAI API reference when implementing the integration.

5. Script Include: keep integration logic reusable

A Script Include can provide a clean server-side abstraction so callers do not need to know how the REST Message is configured.

var OpenAIIntegration = Class.create(); OpenAIIntegration.prototype = { initialize: function() {}, ask: function(userInput) { if (!userInput) { throw new Error('Input is required'); } var requestBody = { model: 'YOUR_APPROVED_MODEL', input: userInput }; var request = new sn_ws.RESTMessageV2( 'OpenAI - Responses', 'POST' ); request.setRequestHeader( 'Content-Type', 'application/json' ); request.setRequestBody( JSON.stringify(requestBody) ); var response = request.execute(); var status = response.getStatusCode(); var body = response.getBody(); if (status < 200 || status >= 300) { gs.error('OpenAI request failed. HTTP status: ' + status); throw new Error('AI service request failed'); } return JSON.parse(body); }, type: 'OpenAIIntegration' };

This is a conceptual implementation pattern. In a real application, use your instance's credential and REST Message configuration, validate inputs, define appropriate timeout behavior, and parse the response according to the API schema you are using.

7. Connecting ServiceNow records to the model

The useful part is where ServiceNow context becomes AI input. For example, an incident summarization flow could retrieve the incident number, short description, description, relevant work notes, service, and selected knowledge context before constructing a request.

ServiceNow Incident ↓ Validate access ↓ Collect approved fields ↓ Optional knowledge retrieval ↓ Build controlled prompt/input ↓ OpenAI API ↓ Validate response ↓ Return summary / recommendation ↓ Human review or workflow action
Important: Do not automatically send every field from a record to an external model. Decide which data is necessary for the use case and apply your organization's privacy, security, retention, and data-handling requirements.

8. Example: Incident summarization

Step 1 — User action

The authorized user requests a summary from the incident form.

Step 2 — Server-side validation

The Script Include verifies that the user can access the incident and that the request is allowed.

Step 3 — Gather context

The server retrieves only the fields needed for the summarization task.

Step 4 — Call OpenAI

The REST Message sends a JSON request using the securely managed credential.

Step 5 — Validate the response

The integration checks HTTP status and response structure before using the model output.

Step 6 — Present the result

The summary can be shown to the user for review rather than silently modifying the incident.

9. Error handling is part of the integration

A successful HTTP request does not guarantee a successful business operation. Network failures, authentication errors, rate limits, malformed requests, timeouts, and unexpected response structures all need explicit handling. OpenAI's API reference documents errors, rate limits, and request identifiers as part of production guidance.

  • Missing or invalid input
  • Authentication failures
  • HTTP 4xx responses
  • HTTP 5xx responses
  • Timeouts and network failures
  • Rate limiting
  • Unexpected or incomplete response data
  • ServiceNow transaction failures

10. Logging and observability

Logging should help diagnose failures without exposing secrets or sensitive payloads. OpenAI documents a unique x-request-id response header and recommends logging request IDs in production for troubleshooting.

  • Integration name
  • Operation name
  • Start/end time or duration
  • HTTP status
  • OpenAI request ID when available
  • Application or transaction context
  • Error category
  • Whether human review was required

Avoid logging the API key, authorization header, or unnecessary sensitive user or record content.

11. Synchronous vs asynchronous design

ServiceNow supports synchronous and asynchronous execution patterns for outbound integrations. Synchronous execution waits for the response, while asynchronous execution can allow the initiating transaction to continue rather than blocking on the external service.

For a user-facing "summarize this record" interaction, synchronous execution may be appropriate when the response is expected quickly. For longer-running or non-interactive processing, an asynchronous pattern may be more suitable.

Design for the user experience: The correct integration pattern depends on latency, transaction importance, failure recovery, expected volume, and whether the user needs the answer immediately.

12. Security architecture

The most important rule is simple: the browser should never own the OpenAI API secret. OpenAI's current authentication guidance explicitly says API keys are secrets and should not be exposed in client-side code.

  • Keep credentials server-side.
  • Use ServiceNow credential management rather than hardcoding secrets.
  • Apply least-privilege access to the Script Include and calling application.
  • Validate record access before sending record data externally.
  • Minimize the data included in requests.
  • Do not expose raw external API errors directly to end users.
  • Rotate credentials according to organizational policy.
  • Review external data handling and retention requirements before production use.

14. Common mistakes

  • Hardcoding the API key: A secret should not live in source code.
  • Calling OpenAI directly from the browser: This can expose the credential.
  • Sending the entire ServiceNow record: More data is not automatically better.
  • Putting all logic in a widget: Sensitive integration logic belongs server-side.
  • Ignoring response validation: Model output should not automatically become trusted business data.
  • No timeout strategy: External services can be slow or unavailable.
  • No audit trail: Production AI integrations need operational visibility.
  • Using stale API examples: Verify the current OpenAI API reference before implementing an endpoint or model.

15. Where this architecture can go next

Once a basic ServiceNow-to-OpenAI integration is working, the same foundation can support richer patterns such as retrieval-augmented generation, structured outputs, tool calling, AI assistants, incident summarization, classification, knowledge workflows, and agentic orchestration.

The architecture should evolve without putting the model call directly inside every business process. A reusable integration layer makes it easier to change prompts, models, authentication, error handling, and observability independently.

Conclusion

A ServiceNow + OpenAI integration is fundamentally an enterprise integration problem with an AI model in the middle. The durable design is to keep ServiceNow responsible for identity, business context, workflow, and authorization while the integration layer securely communicates with the model.

Once those boundaries are clear, the same pattern can become the foundation for custom AI assistants, intelligent workflow actions, retrieval systems, and eventually agentic ServiceNow solutions.
